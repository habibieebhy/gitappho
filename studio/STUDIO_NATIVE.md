# Studio native workflow transport

The existing v7.0.1 action registry and session controller remain authoritative. Studio launches one worker for the chosen registered action using JSON lines, not a terminal handoff. The worker adapts `menu`, `input`, `confirm`, and printed/subprocess output. Static numbered menus are derived from the pinned source AST, not from untrusted output. Confirmation sends the exact expected token only after an explicit choice; Cancel is selected first. Subprocess output is isolated from the protocol. Transcript is memory-only, capped at 2 million characters; overflow blocks further approvals. PgUp/PgDn scroll; Esc cancels the current action, Ctrl+C requests interruption. Git's state is inspected again before another action. No automatic retries or replay.

All 42 action routes use the same bridge. Nine legacy menu definitions are mapped to native choices. Some data entry (file numbers, branch names, commit IDs) remains text entry within Studio. Editing files, browser authentication, and custom hooks may require external tools; the terminal does not hand off to the Classic UI. Noninteractive authentication may fail, in which case Studio displays the result. Direct shell commands and `gitappho classic` remain unchanged. Existing engine restrictions remain. This is not proof of exhaustive Git state coverage.
